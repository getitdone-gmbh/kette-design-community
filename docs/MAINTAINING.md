# Maintaining @getitdone-gmbh/kette-design-community

Repo `getitdone-gmbh/kette-design-community` (renamed from `getitdone-gmbh/kette-design` in 0.4.0; the old npm name `@getitdone-gmbh/kette-design` stops at 0.3.7 and is deprecated).

This repo is the free MIT core of the Get IT Done design system. It is a copy, not a source.

- **Source of truth:** the private Enterprise library, repo `getitdone-gmbh/kette-design-enterprise` (renamed from `getitdone-gmbh/component-library-react`). Its npm package moves from `@getitdone-gmbh/component-library-react` (up to 0.26.x) to `@getitdone-gmbh/kette-design-enterprise` (from 0.27.0); the story sync maps both names. Never change a component here first.
- **Tokens:** repo `getitdone-gmbh/kette-tokens` (renamed from `getitdone-gmbh/figma-design-tokens`), npm `@getitdone-gmbh/kette-tokens` from 5.18.0 (earlier versions as `@getitdone-gmbh/figma-design-tokens`).
- **Customers** get the Enterprise packages through Die Kette ([kette.itdone.de](https://kette.itdone.de)) and [kette-cli](https://github.com/getitdone-gmbh/kette-cli): `kette login <licence key>` sets up npm access to `https://npm.kette.itdone.de/`.
- **Owner of the sync:** the agent `design-system-release-engineer`. Decision record: `getitdone-gmbh/company-playbook/decisions/0004-freier-kern-ui.md`.
- **Monitoring:** `design-system-atlas-keeper` lists this package in the atlas and flags it when it lags behind the library.

## Sync after every library release

1. Note the library version you sync from (e.g. `0.26.7`) and the token version (`@getitdone-gmbh/kette-tokens`, before 5.18.0 `@getitdone-gmbh/figma-design-tokens`).
2. Copy the changed files of every component already in `src/components/ui/` from the library's `@/components/ui/`. Keep the import closure; no domain logic, no client names, no zero components.
   Then sync the stories: `npm run sync:stories -- <path to a kette-design-enterprise checkout at the release tag>`. The script replaces all `*.stories.tsx` in `src/components/ui/` with the library's stories of every component that exists here, skips stories that import components or packages ui does not have (it prints the list), applies the story cuts in `scripts/sync-stories.mjs` (for example the Score Ring story in Progress Circle) and moves the example data to the shared cast. When a story with new names, companies or a new cut shows up, extend the cast table or the patches in the script, never edit a story by hand. Stories stay out of `dist/`, the npm package and the registry.
3. Copy the theme from the token package at that version: `dist/theme_shadcn_zero/theme.css` to `styles/theme.css`, `dist/tailwind.theme.cjs` and `dist/tailwind.preset.cjs` to `tailwind/`, and the changes of `tailwind/preset.cjs` into `tailwind/preset.cjs` (apply the token diff between the two versions, do not copy the file over it): it keeps its local lines `distDir = __dirname`, the package name in the usage comment and the 2.25 stroke rule for 12px glyphs. Then run `npm run theme:prune` (removes Tailwind colours whose variable the zero theme does not declare) and `node scripts/build-document-surface.mjs`. `src/lib/theme-vars.test.ts` fails when the Tailwind config references an undeclared variable or when `styles/theme.css` loaded alone does not declare or resolve a Tailwind-referenced or pair variable in `:root`, the dark blocks and the paper scope (the kette-tokens `check:standalone` gate), `src/lib/theme-pairs.test.ts` when a fill/text pair is incomplete or below 4.5:1 (the kette-tokens `check:pairs` and `check:scopes` gates for the zero theme, plus the status pairs). Keep `PAIRS` in `scripts/theme-pairs.mjs` equal to kette-tokens `scripts/color-pairs.js`. A failing pair is fixed in kette-tokens, never here.
4. Example data uses the shared fictional cast (Nordwind Handel, Tobias Lindner, Lena Hartmann, Example Studio, `@example.com`).
5. `npm ci`, `npm run typecheck`, `npm test`, `npm run build`, `npm run build-storybook`, `npm run registry:build` and `npm pack --dry-run` all green locally. Open a few stories of the build in light and dark mode.
6. Bump the version in `package.json` (minor for new components, patch otherwise), update the version, the component counts (from the exports in `src/index.ts`) and the story counts (`storybook-static/index.json`, entries of type `story`) in `README.md`, add the row to the sync history below, commit as Alexander Friedl, push once. The README does not repeat the library and token versions, it links to the sync history.
7. Rebuild the shadcn registry with `npm run registry:build` and publish `public/r` to the itdone app `zero-design-public` (served at `zero-design.itdone.de/r`).
8. After the merge to `main`, tag the merge commit and push the tag: `git tag -a vX.Y.Z -m vX.Y.Z && git push origin vX.Y.Z`. The tag starts `.github/workflows/release.yml`: it checks that the tag equals the `package.json` version, runs typecheck, tests and build, publishes to npmjs.com through npm trusted publishing (no token, with provenance), publishes the same version to GitHub Packages (listed under "Packages" on the repo page) and creates the GitHub release with the version's section of `CHANGELOG.md`. Each step skips a version that is already there, so a failed run can be re-run. Nobody publishes from a laptop any more.
9. Verify: the run is green, `curl -s https://registry.npmjs.org/@getitdone-gmbh%2fkette-design-community` shows the new version as `dist-tags.latest`, the npm page shows the provenance badge, and the repo page lists the version under "Packages". The trusted publisher is set on npmjs.com (package settings, GitHub Actions, repo `getitdone-gmbh/kette-design-community`, workflow `release.yml`); when the repo or the workflow file is renamed, update it there first. Old names are deprecated once, after the first release under the next name: `@getitdone-gmbh/ui` (done, pointer to kette-design) and `@getitdone-gmbh/kette-design` (open since 0.4.0: `npm deprecate @getitdone-gmbh/kette-design "Renamed to @getitdone-gmbh/kette-design-community" --registry=https://registry.npmjs.org`).
10. Tell the atlas keeper so the atlas shows the new state.
